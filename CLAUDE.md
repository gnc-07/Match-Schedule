# Matchday Planner: instructions for Claude Code

Read this before making any change. README.md explains the site to visitors; MAINTAINING.md holds the owner's setup and maintenance notes; this file is for you.

## What this is
A static website (GitHub Pages) listing upcoming Premier League, La Liga, Bundesliga, Brasileirão, CONMEBOL Libertadores, UEFA Nations League (League A) and national-team friendly fixtures, plus every Formula 1 session, with cross-checked kick-off times, live scores, and a subscribable calendar feed.
- Repository: `gnc-07/Match-Schedule` (no "s" at the end). Default branch: `main`.
- Live site: https://gnc-07.github.io/Match-Schedule/ (calendar feed: `/soccer.ics`, Portuguese: `?lang=pt`).
- The owner is based in Edmonton, uses Fedora Linux, and is learning as they go.

## Rules that must hold after every change
1. **Accessibility and quality bar:** Lighthouse 90+ in Performance, Accessibility, Best Practices and SEO on mobile and desktop, in both languages. axe-core: zero WCAG 2.2 AA violations in light and dark themes, English and Portuguese, at 390px, 1280px and 1920px wide. Controls at least 44px tall (32px minimum for small inline icons like stars). Visible focus rings. Every text colour must meet 4.5:1 contrast on its background in both themes.
2. **Colours only through the CSS tokens** in `:root` and the two dark-theme blocks. A new colour is added to all three blocks. High contrast (Settings) has its own three blocks (`:root[data-contrast="high"]` and its two dark versions) that override only the tokens needing a stronger value; when a new colour needs one, add it to all three of those too.
3. **Every visible string goes in the `I18N` table** in `js/i18n.js`, in both `en` and `pt` (Brazilian Portuguese). Never hard-code English text in markup or scripts.
4. **Audience:** the site should be easy for older, less technical visitors. Prefer labelled buttons over icon-only ones, plain wording, large targets, and settings that apply immediately. Keep the design minimal.
5. **Verification rule for kick-off times** (in `resolve()` in `build_schedule.py`): a time is "verified" only if an official source gives it or at least two independent sources agree. Do not weaken this.
6. **At least two independent sources for every competition.** The owner has asked for this explicitly. A competition's schedule must come from at least two independent sources so that `resolve()` can cross-check its times: one that lists the matches and one that checks them (Formula 1: Jolpica-F1 and OpenF1; Libertadores: ESPN and Wikipedia; the four leagues: football-data.org, checked against openfootball and ESPN's scoreboard; hand-kept files: at least two reports per match, or an official one). Never add a competition with only one source; if no second free source can be found, tell the owner before building anything.
7. **No em dashes** in any user-facing text or in messages to the owner.
8. **Outside data is untrusted.** In the page's scripts (`js/`), everything from `fixtures.json`, ESPN, OpenLigaDB, Jolpica-F1 or Wikidata goes through `esc()` before it becomes HTML (numbers too), every outside link through `safeUrl()`, and times through `toDate()`. A new outside service must be added to the Content-Security-Policy `<meta>` at the top of `<head>` (`connect-src` for `fetch`, `img-src` for pictures), or browsers block it. In Python, downloads go through `common.fetch`, and anything written from a model's reply (`research.py`) is type-checked and length-limited.

## How to test before committing
```bash
python3 build_schedule.py        # builds fixtures.json and soccer.ics locally (do not commit these)
python3 -m http.server 8000      # then open http://localhost:8000 ; Ctrl+C stops it
```
Check: English and Portuguese (`?lang=pt`), light and dark theme (the sun and moon button), a phone-width window, a laptop-width and a full-width window (the wide-screen layouts), keyboard-only use (Tab, Enter, Escape).

Automated checks (needs Node.js; run `npm install` once to download the tools, and `npx playwright install firefox webkit` once for the browser checks):
```bash
npm run format            # after editing js/ or index.html: lays out the JavaScript the standard way (CSS and markup are left as written)
npm test                  # every group through tests/run.mjs, about 2 minutes: format, python, security, accessibility, design, browsers, motion side by side (JOBS, default 4, each on its own port), then speed (Lighthouse) alone; a passing check prints one line, a failing one in full; ends with a summary; exits non-zero if anything failed
npm run test:quick        # the fast groups only (format, python, security, design, browsers), under a minute
npm test -- browsers accessibility  # only the groups named; --skip speed for all but those named; --list to see them; --verbose for every line; --serial for one at a time with live output
npm run test:browsers     # Chromium, Firefox and WebKit (Safari's engine): the list, widths, fonts, control sizes, script errors, and a visitor's clicks and keys; pictures in screenshots/browsers/; a browser that is not installed is skipped (PART in the summary); add installed Chrome or Edge with node tests/browsers.mjs chrome edge
npm run test:py           # the Python scripts (resolve(), calendar escaping and folding, CazéTV matching, research.py input checks and a full run against a stand-in for the Claude API); no Node needed: python3 -m unittest discover -s tests
npm run test:security     # hostile data in fixtures.json, ESPN and Wikidata answers must never run or become a link; no CSP violations
npm run test:axe          # axe-core WCAG 2.2 AA, six views at a time (AXE_WORKERS), each in its own private window: light/dark, en/pt, 390/1280/1920px; menus closed, filter sidebar hidden, Settings, Calendar, Tables (a league and F1), match details, F1 race weekend, high contrast
npm run test:corners      # rounded shapes close inside another rounded shape must have parallel corners (inner = outer less border and gap)
npm run test:layout       # wide screens, scrolled to the end: the filter sidebar, its bar and the right-hand column never cover the footer
npm run test:lighthouse   # mobile and desktop, en and pt; every category must be 90+; HTML reports in lighthouse-reports/
npm run test:motion       # animations: only opacity and transform, shared speeds; Chromium, plus Firefox when FIREFOX_PATH is set (npm test skips its frame timings, which never pass or fail, with TIMINGS=0)
```
Run `npm run format`, then `npm test`, after `python3 build_schedule.py` and before every commit that touches `index.html`, `styles.css` or `js/`. A new test file joins a group in `GROUPS` in `tests/run.mjs` (it must use `PORT` from `server.mjs`, never a fixed port, since checks run side by side) (and gets its own `test:` script in `package.json`), so `npm test` stays the one command. Pushing a branch other than `main` also runs the suite on GitHub (`tests.yml`), where Firefox and WebKit are always installed; read the result in the Actions tab. The JavaScript (`js/` and the `<head>` scripts) is laid out by Prettier (120 characters wide); the CSS and HTML keep their compact hand-written style. Every test sees the published page (`tests/server.mjs` builds it with `publish_site.py`), so a change to how the page is put together is tested too. The axe run also covers the League tables window, the match details panel and high contrast, using the sample data in `tests/mock-data.mjs` in place of ESPN, Wikidata and OpenStreetMap. `node tests/screenshots.mjs` saves preview pictures with that sample data in `screenshots/` (git-ignored), for showing the owner design options before anything is published. The tests start their own server on port 8123 (`tests/server.mjs`: it gzip-compresses text files the way GitHub Pages does, so Lighthouse measures what visitors download) and use the system Chromium, else the one Playwright downloaded (`PLAYWRIGHT_BROWSERS_PATH`, as in a cloud container) (override with `CHROME_PATH`; when run as root, as in a cloud container, they add Chromium's `--no-sandbox`). `browsers.mjs` checks control heights (44px, 32px for stars); three controls were already below 44px when it was written and are listed in it at their size then (date range buttons 38px, team search 42px, the Sources toggles 32px), so check those by hand when you change them. `node_modules/` and `lighthouse-reports/` are git-ignored; `tests/` and `package.json` are never published (the workflow copies only the site files).

## How to publish
```bash
git restore fixtures.json soccer.ics streams.json   # drop local rebuilds of generated files
git add <the files you changed>
git commit -m "<short description>"
git pull --rebase                       # AFTER committing: fetch the workflow's data commits and replay ours on top
git push
```
Order matters: `git pull --rebase` refuses to run while there are uncommitted changes, so always commit first. Pushing to `main` starts the workflow, which republishes the site in about two minutes. Tell the owner to check the Actions tab. Visitors need no hard refresh: GitHub Pages lets browsers reuse `index.html` for up to 10 minutes (`cache-control: max-age=600`), `fixtures.json` is always fetched fresh, and a page left open re-checks `fixtures.json` when the visitor returns and every 15 minutes, reloading itself (only on return) when the `site` fingerprint of the published page (`index.html`, `styles.css` and `js/` together) changes. The owner can see a change at once with Ctrl+Shift+R, or wait 10 minutes and reload normally.

### Branch names
When work goes through a branch and pull request, name the branch after what it changes: a few lowercase words joined by hyphens, such as `match-details-panel`, `fix-live-scores` or `readme-setup-steps`. Never use generated names like `claude/inspiring-rubin-k5ruq0`. This holds for every branch you create, even when a session hands you a generated branch name: create a descriptively named branch and push to it instead (the owner has asked for this explicitly). When one piece of work is split into several pull requests that must be merged in order, start each name with its place in the order: `1-faster-loading`, `2-contrast-settings`.

### Pull request descriptions
Follow `.github/pull_request_template.md` (GitHub fills it in when a pull request is opened on the website; when opening one through a tool, copy its headings yourself). The **Before and after** section is required:
- Anything that looks different: a before and an after picture of each changed screen, at 390px and 1280px (and dark theme or Portuguese when the change touches them). Take the "before" pictures from `main` before editing, with the same sample data and steps as the "after" ones.
- Anything that behaves or feels different, even with no visible change (a speed fix, a bug fix, an animation): a before and an after video of the same steps, recorded on the same machine. For speed, add the Lighthouse numbers too.
- Only changes a visitor cannot see or feel (tests, workflow, documentation, data sources) may say "No visible change", with the reason.

Pictures and videos are attached to the pull request, never committed (`screenshots/` is git-ignored). If you cannot upload them yourself, send them to the owner in the session, write "owner to attach" in the empty table cells and after the Before and After video lines, and tell the owner step by step how to drag them in (Edit on the pull request description, drag the file into the box, Update comment).

## How to talk to the owner
- Always give instructions step by step, stating exactly what to click or change.
- Explain every terminal command in full: what each part, flag and subcommand does.
- Show what changed (a screenshot description, or suggest they open the local preview) before pushing design changes, so they can steer.
- Be honest about limits and anything not tested.

## Current design (September 2026)
- Header: brand on the left; a sun and moon button (icon only, 44px, 48px on phones; named "Switch to dark theme" or "Switch to light theme" for screen readers and as a tooltip) that flips between light and dark (the only theme control; until it is used the site follows the device), sitting on the brand's row on phones; **Settings** (two small group headings, Region: language and time zone; Appearance: a "High contrast" tick box, an "Animations" tick box, text size Normal, Large or Extra large with each choice shown in its own size; small "Close ×"; no explanatory hints), **Tables** and **Calendar** buttons on the right. - Match details: a "Match details" button on each card opens a panel over the list (address `?match=<uid>`, so Back closes it and the link can be shared): score, timeline of goals, cards and substitutions (icon plus text label), line-ups with formation and coach, Add to my calendar (one .ics), Share, the league's table, and the stadium with a small OpenStreetMap map (plain tile images located through Wikidata; no map script). Data from ESPN's public match summary, refreshed every 30 seconds during a match.
- Race weekend (F1): the race card's "Race weekend" button opens the same panel (address `?match=f1|<season>|<round>`): Grand Prix, dates and a board (next session, on now, or winner); the weekend schedule with pole or winner per session; results (race and sprint with a podium, places gained, fastest lap, retirements; qualifying with Q2 and Q1 dividers), driver stars (saved as `f1favs`) highlighting rows; the championship (drivers top 10 plus starred drivers, or teams); the circuit as a track diagram (an SVG of `circuit.layout`, north up except for f1-circuits-svg drawings, whose credit line (`f1TrackAlt`) says so, a dot at the start/finish line, lap length and first Grand Prix, a link to OpenStreetMap), falling back to the OpenStreetMap tile map when a circuit has no outline. Results and standings come from Jolpica-F1 in the visitor's browser (it allows any origin), one request at a time, re-checked every 5 minutes around sessions. On phones the places-gained arrow and the points move under the name and time. Team colours are thin decorative bars (`--t-*` tokens) always next to the written team name.
- Panels and the text size: dialogs are sized in % (not vw/dvh), because the page zoom of Large and Extra large text does not apply to viewport units.
- **Tables** opens the league tables (ESPN standings, starred teams highlighted; for the Nations League, League A's four group tables, and for the Libertadores its eight groups (A to H), one under another (`GROUPS` in `js/tables.js`), with no backup when ESPN does not answer; a group match's table button brings its group into view) and, under a Formula 1 chip, the championship with a Drivers / Teams switch (Jolpica-F1 `current` standings, starred drivers highlighted).
- Match panel and tables: spacing scale 4, 8, 12, 16px; cards 16px padding and 14px corners; controls 10px corners. A rounded shape sitting close inside another is given parallel corners: the outer radius less the border and the gap (the text size choices 5px, segmented buttons 6px, the Close button in a window's corner 7px); `npm run test:corners` checks this.
- Finished matches stay a day with the final score (ESPN, else the league feed's result from `build_schedule.py`).
- Backups when ESPN does not answer: the Bundesliga's scores (Live now and cards), goals (Match details, no line-ups or cards) and table come from OpenLigaDB (`BACKUP_BOARD`, `oldbSummary()`, `oldbTable()`; no match clock); the other leagues' tables from `tables` in `fixtures.json`. Each names its source on screen (`liveNoteAlt`, `mdSrcAlt`, `ltSourceAlt`, `ltSourceCalc`). A match found through the backup is not remembered, so ESPN is tried again at the next update. `npm run test:security` covers these with ESPN switched off.
- Motion: two shared speeds, `--dur-s` (0.18 s: things that change in place, such as button colours, arrows, menus unfolding) and `--dur-m` (0.28 s: things that arrive or move, such as panels, sheets, the list, the theme, a bounce, the page gliding to a new layout), and two curves: `--ease` for what arrives (brisk, then settles softly) and `--ease-soft` for what leaves, for the page gliding a long way, and for the panel arriving beside the list with the page gliding (starts and ends gently, so nothing lurches, and a fade shows as a fade), all in the Motion block at the end of `styles.css`; script animations read the same values through `move()`, `DUR()` and `cssVar()`. Only opacity and transform move (plus colour transitions on buttons), and nothing moves on page load. Panels rise (beside the list: slide in from the right as far as the header's buttons move, in step with them, so it pushes them aside rather than covering them (`makeRoom()` in `js/race.js`), and the list, the sidebar and the header's parts glide over to make room (`pageParts()`: the brand, the theme button and the other buttons each keep their width, so they only glide; the "Updated" line under the header gets narrower and wraps anew, which no transform can smooth, so a copy of it as it was fades out where it was while it fades in where it is, `crossFade()`), while the right-hand column fades out where it was under the arriving panel, kept in place by `data-rail-out`, `railOut()`), Settings and Calendar drop down (slide up as a sheet on phones), sources unfold (these four open inside a `<details>`, which Chromium stops styling once closed, so `rearm()` in `js/list.js` reads the hidden part's style after each closing, or the opening would play only the first time), a new star bounces (team stars and F1 driver stars), the theme switch and every Settings choice that changes the whole page (high contrast, text size, language, time zone) cross-fade the page (`fadePage()`: View Transitions, where supported; button colour transitions are paused meanwhile with `data-theming`), the first few days of the list rise in turn after a filter change and after "Show more" (not after automatic updates). Everything that closes or goes away plays its opening backwards, taking as long as the opening, on `--ease-soft`, before it goes (`leave()`; opened again meanwhile, `stay()` keeps it): panels sink (beside the list: slide back out to the right, in step with the header's buttons, while the page glides back at the same time and the right-hand column fades back in; the panel keeps its place meanwhile through `data-pane-out`, and the match shown keeps its place on screen: the list gets wider, so the matches above it get shorter, and browsers turn off scroll anchoring when the page's padding changes, so `shut()` scrolls by what they lost itself; `tests/browsers.mjs` checks this at 1650px), menus fold up (sheets slide down), sources and "How to subscribe" fold away, and the small filter controls (Custom dates, Clear filters, Include F1 practice sessions, the search box's clear button) unfold into place and fold away (`reveal()`, not during page load). The filter sidebar, the list and the right-hand column move as one: hidden, the sidebar slides out to the left as it fades while the list and the column slide over by as much at the same speed, and the bar fades in; shown again, the same backwards; pressed again on the way, everything turns back from where it is (`glide()` stops a glide still running before it measures) (`setSide()`; the sidebar is kept in its place meanwhile by `data-side-out`, as the column is by `railOut()`; no width changes, so nothing jumps at an edge or overlaps: `glide()`: transform only, divided by the text-size zoom; a part inside another that glides, such as Live now in the right-hand column, is left to move with it, or it would move twice and jump; the list is followed through a match on screen, the match shown when details open or close beside it, because the list's own edge can move thousands of pixels when the matches above the window change height). Opening details beside the list also brings the match to the middle of the window by gliding (the panel is placed beside the list before it opens, so moving focus into it scrolls nothing), and closing never scrolls the page: the list's history entry is told not to restore its scroll (`history.scrollRestoration`, set around `pushState` and back to auto after `popstate`). New content in the same place (another league in Tables, Drivers or Teams, the Race weekend results and championship switches, another match beside the list) fades in quickly (`swapIn()`), and "Link copied" unfolds; and a changed score bounces while a soft gold light (`--glow`) pulses out from behind it twice (3 x `--dur-m` each), under the team names, clipped to that match's row (for the match shown beside the list, to its outline's outer edge, so the outline stays whole); nothing is marked while animations are off. The "Animations" tick box follows the device's "reduce motion" setting until used (`motion`: auto, on, off); off sets `data-motion="off"` on `:root`, and the last rule in `styles.css` stops every CSS animation and transition; `move()` checks `motionOn()`. `npm run test:motion` (`tests/motion-check.mjs`) checks that only opacity and transform animate and every length is a shared speed, and follows closing and gliding frame by frame (on monitors too, with Live now showing: it and the key must move and fade as one, and the list never reaches into it; Match details opening, closing or reopening beside the list, the header's parts glide (none goes half its way in one frame) and the panel never covers the buttons; hiding and showing the filters, the header stays put, the list keeps its width and moves in step with the sidebar) ("smooth": a closing starts softly, the page never jumps while something closes (a scroll that keeps the match on screen in place is no jump), the list never glides more than 50px in a frame), in Chromium and, with `FIREFOX_PATH` set, Firefox, and saves halfway pictures; `node tests/motion-videos.mjs` records videos (needs ffmpeg with H.264; set `FFMPEG`). Both write to `screenshots/`. axe runs with "reduce motion" so it measures settled panels. Headless Firefox screenshots do not show View Transitions; record a real Firefox window (Xvfb plus ffmpeg `x11grab`) to see them.
- Colours: every colour is a token, including the live box and shadows. The scheme is "Navy and gold"; high contrast (Settings) is the only alternative.
- League pictures: each league button shows a round picture from `CREST` in `js/settings.js` (the country's flag for the four leagues, a globe for friendlies, the emblem of the Libertadores' official logo (CONMEBOL's trademark, used non-commercially: its five gold bars, `--flag-lib-gold` on `--flag-black`, traced from ESPN's copy of the logo without the lettering or the sponsor's name), the flag from the Nations League's official logo (UEFA's trademark, used non-commercially; 6 `--flag-unl-*` colours plus `--flag-white` and `--flag-black`), the F1 mark from Simple Icons), falling back to the letter badge `abbr`. The Libertadores' own colour is olive (`--lib`), chosen as the colour most distinct from every other league's and from `--accent` in both themes (compare candidates by colour difference, not by eye). Flag colours are the `--flag-*` tokens, the same in every theme.
- Fonts: Big Shoulders Display (headings), Instrument Sans (text, times and letter badges; one variable file holds weights 400 to 700, 30 KB, in place of three files of 51 KB), Azeret Mono (scores and code; not needed at first load).
- Speed: visitors download one file, as `publish_site.py` puts the page together (no extra request before the first paint, and an old script can never meet a new page), without its comments (about 60 KB compressed); `fixtures.json` is requested from `<head>`, is written compactly (one match per line), and the list is only redrawn when it changed. A redraw rebuilds only the days whose markup changed (`drawList()` in `js/list.js`: `render()` hands it one part per day, and an element is kept only when its markup is identical, so nothing else may change list elements in a way the markup does not show), and days far from the window are not laid out or painted (`content-visibility:auto` on `.day`, height guessed from `--n`, its number of matches; the day of the match shown beside the list is always drawn, as its outline reaches past the day's edge). So a test must bring a list item into view before clicking it (`showMatch()` in `tests/mock-data.mjs` does), or the click can land where the item was guessed to be. The animation speeds are read once (`cssVar()` remembers them).
